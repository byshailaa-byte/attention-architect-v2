> **⚙️ HOW TO READ THIS FILE**
>
> This is both a **finished example** (a complete Storm + Pusher report) and the **production template** for all 32 archetype × pattern combinations. Every piece of text falls into one of three types:
>
> - **`[SHARED]`** — identical in every report, written once. Never changes.
> - **`{{slot}}`** — a variable filled from data. The five slot families are defined below.
> - **Plain prose** — the Storm+Pusher-specific fill, shown so nothing is abstract. In production this is authored per-archetype or per-pattern.
>
> **The five slot families:**
> | Slot family | Source | Count |
> |---|---|---|
> | `{{child.*}}` | the 8 child archetypes | 8 variants each |
> | `{{parent.*}}` | the 4 parent patterns | 4 variants each |
> | `{{fit.*}}` | the child×parent pair | authored per pair (the flagship content) |
> | `{{objective}}` | landing-page concern chip | 6 phrases (from personalization spec) |
> | `{{name}}` `{{child_name}}` `{{age_band}}` | captured data | direct fill |
>
> **Authoring order (do NOT write one full report at a time):** write each SECTION across all archetypes/patterns before moving to the next section. Section 2 for all 8 archetypes, then Section 3 for all, etc. This keeps voice and structure consistent across the set — the same discipline as the LMS.
>
> **Slot count reality check:** a full report is ~40 filled slots. Because slots draw from small pools (8 + 4 + 6 + per-pair fit content), the total authored content is roughly: 8 archetype voices + 4 pattern voices + 32 fit passages + 6 objective phrases — a few hundred short passages, NOT 32 hand-written reports.

> ### 🔴 Decision log — composed, not pair-specific (locked)
> `stay_path` and `change_path` were pair-specific in the original spec (32 fully unique passages, like the fit-reveals). **Changed to composition: 8 archetype bases + 4 pattern clauses = 12 authored passages**, not 160.
>
> **Why this doesn't cost what it would have in Section 3:** the fit-reveal has to be pair-specific because it names an *interaction* — a mechanism that only exists between this exact child and this exact parent. Section 7's stakes are **additive, not interactive**: "here's what continues if the archetype's pattern doesn't shift" plus "here's what this parent's pattern does under stress" are two separable statements, not one collision. Composition doesn't flatten the insight here the way it would in Section 3.
>
> **`[SHARED]` rule, unchanged:** the "stay" clause names a real cost without catastrophizing — no deterministic doom, ever, in either the base or the clause.
>
> **7 remaining archetype bases + 3 remaining pattern clauses = Session 4's actual scope for this section** (not 31 pairs × 2 paths).
